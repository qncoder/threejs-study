# 导出修改后 GLB 设计

## 目标

在“新建 Object3D”按钮旁边增加“导出模型”按钮，用来下载一份包含当前编辑结果的新 `.glb` 文件。

导出的模型需要保留：

1. 当前会话中新建的 Object3D 节点。
2. Object3D 的重命名结果。
3. 拖拽调整后的父子关系。
4. 当前节点的位移、旋转、缩放。

浏览器不能直接覆盖用户选择的本地文件，所以本功能只下载一个新的 GLB 文件，不改写原始文件。

## 当前情况

项目已有两类导出：

- “导出结构”：下载 JSON，用于离线查看节点列表。
- “导出姿态”：下载 JSON，用于保存节点变换数据。

这两类 JSON 都不是模型文件，重新打开原始 GLB 时不会自动带回新增 Object3D。要把新增节点真正写进模型文件，需要导出新的 GLB。

## 方案选择

采用 Three.js 自带的 `GLTFExporter` 导出当前模型对象，并设置 `binary: true` 生成 `.glb`。

原因：

- 当前模型已经以 Three.js 对象树形式存在，新增 Object3D 和拖拽换父级都已经反映在 `currentModel` 上。
- `GLTFExporter` 会按当前对象树导出节点层级和变换，不需要自己拼 GLB 数据。
- 保留现有“导出结构”“导出姿态”功能，避免影响已有工作流。

## 交互设计

在节点列表标题右侧按钮组中，把按钮顺序调整为：

1. 新建 Object3D
2. 导出模型
3. 刷新

按钮状态：

- 未加载模型时禁用“导出模型”。
- 加载模型后可点击。

点击后：

1. 停止当前动作播放。
2. 刷新模型世界矩阵和节点结构。
3. 导出二进制 GLB。
4. 下载文件，默认命名为 `<原文件名>-edited.glb`。
5. 状态栏显示导出成功或失败原因。

## 代码结构

新增一个独立模块 `src/modelExport.js`，负责：

- 调用 `GLTFExporter`。
- 封装 Promise 形式的导出函数。
- 生成导出文件名。

`App.vue` 只负责：

- 按钮入口。
- 调用导出函数。
- 触发下载。
- 更新状态栏。

这样可以让导出逻辑单独测试，避免把更多逻辑堆进页面组件。

## 错误处理

以下情况给出状态栏提示：

- 未加载模型：提示“请先加载模型”。
- 导出器返回异常：提示“模型导出失败”并保留错误信息到控制台。
- 导出结果不是二进制数据：按失败处理。

## 测试

新增 `src/modelExport.test.js`，覆盖：

1. 文件名生成：`F309.glb` 生成 `F309-edited.glb`。
2. 文件名生成：没有有效名称时生成 `model-edited.glb`。
3. 导出函数会用 `binary: true` 调用导出器。
4. 导出函数返回二进制结果。

现有 `modelGrouping.test.js` 已覆盖新增 Object3D 和拖拽换父级。导出测试不重复验证这些行为，只验证导出函数会使用传入的当前模型对象。

