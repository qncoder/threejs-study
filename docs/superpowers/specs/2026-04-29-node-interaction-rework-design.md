# 节点交互与结构整理设计

## 目标

围绕节点列表重做一层统一的节点交互，满足以下目标：

1. 节点支持右键菜单，提供脚本编辑、节点信息查看、删除、聚焦。
2. 节点行支持隐藏/显示，隐藏后节点不可被画布选中。
3. 节点详情不再常驻右侧，改为弹窗展示，并支持分组折叠。
4. 旧的“绑定脚本”“JS 控制”入口全部移除，统一收口到节点脚本弹窗。
5. 梳理 `App.vue` 里过于集中的节点交互逻辑，拆出职责明确的模块。
6. 补一份项目结构说明文档，写清模块职责和交互规则。

## 当前问题

当前实现的主要问题集中在 [src/App.vue](</C:/Users/qinan/Documents/New project/src/App.vue:1>)：

- 节点列表、节点详情、脚本执行、隐藏子 Mesh、模型点击选中、Three.js 场景控制都堆在一个文件里。
- 节点信息常驻右侧，和节点列表是两个平行入口，交互分散。
- 脚本能力偏向“临时执行”，没有统一的节点级弹窗管理。
- 隐藏逻辑只覆盖“隐藏某个节点下的 Mesh”，没有统一的节点可见性模型。
- 模型拾取只看是否命中节点，没有结合“隐藏后不可选中”的规则。

## 设计范围

本次只处理“节点交互层”和必要的结构整理，不重写整个渲染与模型加载流程。

保留：

- Vite + Vue 3 + Three.js 基础结构
- 当前模型加载、动作演示、姿态导入导出
- 当前节点树与 Three.js 对象之间的映射方式

调整：

- 节点交互入口
- 节点可见性规则
- 节点信息展示方式
- 节点脚本管理方式
- 节点聚焦能力
- `App.vue` 的职责边界

## 方案选择

本次采用“中等力度拆分”的方案：

- 把节点右键菜单、节点可见性、节点聚焦、节点信息组装、脚本绑定逻辑拆成独立模块。
- `App.vue` 保留页面编排、主要状态、Three.js 生命周期和跨模块协调。
- 不做整项目大规模重构，避免影响现有模型查看、动作播放和姿态功能。

这样做的原因：

- 本次需求主要都落在节点交互层，单独整理这一层收益最高。
- 完全重构 `App.vue` 风险过高，测试回归成本大。
- 先把节点交互边界清楚，后续再拆渲染层会更稳。

## 交互设计

### 节点列表

每个节点行保留左键选中能力，同时增加以下交互：

- 左键点击节点名：选中节点。
- 右键点击节点行：打开右键菜单。
- 节点行显示“隐藏/显示”切换按钮。
- 节点折叠按钮继续保留，用于折叠树结构。

节点行不再直接承载脚本编辑和节点详情的主入口。

### 右键菜单

右键菜单固定 4 项：

1. 编辑脚本
2. 查看信息
3. 删除
4. 聚焦

说明：

- “编辑脚本”打开节点脚本弹窗。
- “查看信息”打开节点信息弹窗。
- “删除”只允许删除安全可删的节点。默认按“当前会话里新建的 Object3D 可删，原始模型节点不可直接删除”处理。
- “聚焦”将相机平滑移动到当前节点附近，并把控制器目标对准节点中心。

### 脚本弹窗

脚本弹窗由右键菜单打开，统一承载原本分散在右侧面板的脚本能力。

弹窗内容：

- 节点名称、类型、路径
- JS 多行编辑器
- 可用辅助方法说明
- 执行结果提示

底部按钮固定为：

1. 执行
2. 保存绑定
3. 清除绑定
4. 关闭

行为规则：

- 打开弹窗时，优先加载当前节点已绑定脚本。
- 没有绑定脚本时，按当前变换生成默认脚本模板。
- “执行”只执行编辑器当前内容，不自动覆盖绑定。
- “保存绑定”把当前脚本写入节点 `userData.controlScript`。
- “清除绑定”删除节点绑定脚本，并恢复默认脚本模板。
- 执行成功后，刷新节点结构、选中框和显示信息。

### 节点信息弹窗

节点信息不再常驻右侧。

改为右键菜单 `查看信息` 打开弹窗，并支持分组折叠。建议分为以下折叠组：

- 基础信息：名称、类型、路径
- 层级信息：父节点、子节点数量、树深度
- 角色信息：机构角色、说明、调节建议
- 几何信息：是否为 Mesh、几何体类型、材质
- 变换信息：局部位置、局部旋转、局部缩放、世界坐标

默认各组可折叠，避免信息过长。

### 隐藏/显示

用户确认的规则如下：

- 如果节点是 `Object3D`，隐藏时影响整个子树。
- 如果节点是 `Mesh`，隐藏时只影响自己。

补充一致性规则：

- 父节点隐藏时，子节点即使自身标记为显示，也仍然不可见。
- 父节点恢复显示后，子节点再按自己的隐藏状态决定是否显示。
- 隐藏后的节点不可被画布点击选中。
- 如果当前选中的节点被隐藏，立即清空选中态，并移除包围框和变换控件。

### 聚焦

`聚焦` 操作的规则如下：

- 优先计算当前节点及其可见后代的包围盒。
- 如果当前节点没有可用几何体，则回退到节点的世界坐标。
- 相机位置和 `OrbitControls` 目标点采用平滑过渡，不做瞬移。
- 聚焦时保持当前观察方向，只调整距离和目标点，避免用户迷失方向。

## 删除规则

删除节点时采用保守策略：

- 当前会话里通过“新建 Object3D”创建的节点可以删除。
- 原始模型自带节点默认不可直接删除。
- 不允许删除模型根节点。
- 删除当前选中节点后，自动清空选中状态并刷新结构。

这样可以避免误删原始模型结构，降低数据破坏风险。

## 风险与约束

### 1. 删除能力的边界

Three.js 节点删除本身不复杂，但原始模型节点直接删除会让结构不可逆地变化。为控制风险，本次只开放安全删除。

### 2. 隐藏与拾取一致性

隐藏规则必须同时作用在：

- 树节点显示
- 模型可见性
- 画布拾取

否则界面和模型状态会不一致。

### 3. App.vue 拆分力度

本次只拆节点交互层，不重写整个场景控制层。目标是把结构理顺，而不是做一次全量重构。
